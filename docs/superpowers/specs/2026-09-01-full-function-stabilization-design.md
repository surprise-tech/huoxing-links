# 链接 SaaS 非支付全功能稳定化设计

日期：2026-09-01
状态：已获用户批准，进入实施计划
基线：`de6c4cd6ba888d2d7f0d8980a4369244830104bc`

## 1. 背景与目标

当前仓库包含 Laravel API（`serve/`）、Vue 3 管理端（`admin/`）、外部跳转壳（`jump/`）和 uni-app 落地小程序（`mini_programs/`）。现有界面和主要业务模型已经存在，但全新安装、会员状态、跳转解析、外部接口、二维码轮换、测试隔离和部署链路存在断点，不能仅凭页面展示或 HTTP 200 认定可交付。

本项目第一阶段的目标是一次性交付“除支付外的全功能版本”：所有仓库内公开展示的非支付功能必须可安装、可操作、可验证，并在测试环境完成浏览器与手机验收。套餐定价、月付/年付购买、微信/支付宝支付、退款、自动扣款、发票和财务对账延后到独立阶段。

## 2. 成功标准

只有同时满足以下条件，第一阶段才可宣称完成：

1. 从空数据库执行迁移和初始化后，管理员、普通用户和三天体验资格可以正常使用。
2. 管理端可以登录，并完成公告、素材、域名、小程序池、用户、套餐权益和全部链接类型的管理。
3. 六种链接类型均能创建、编辑、启停、删除、生成分享地址，并得到类型正确的跳转结果。
4. 个人微信二维码支持顺序/随机轮换、单码额度、过期时间和二维码展示。
5. 会员有效期、链接数、小程序池数量、UV 去重和额度周期均能正确限制。
6. 额度周期以会员开通时间为锚点滚动。例如 9 月 15 日开通，则第一个周期为 9 月 15 日至 10 月 15 日；锚点为 29–31 日且目标月份缺少该日时，使用该月最后一天。
7. 管理端类型检查与生产构建通过；后端单元、功能和集成测试通过。
8. 测试域名、DNS、Nginx、HTTPS、PHP-FPM、MySQL、Redis、队列和定时任务作为发布环境门逐项验证；环境门失败时状态为“外部阻塞”，不把它误报成代码测试失败，也不能宣称整体发布完成。
9. 浏览器实际建链成功，手机端按链接类型验证真实结果；外部平台凭据缺失时明确列为用户控制的验收门，不以模拟结果替代线上结果。
10. 六类链接均能返回可打开的 canonical 分享地址；停用、用户禁用、会员过期和越权引用均有稳定错误码且不写访问日志。
11. API 响应、缓存、访问日志和前端状态中均不得出现小程序 Secret、短信密钥或其他明文凭据。
12. 上线产物的用户界面、标题、Logo、客服、版权和帮助文案不出现“火星快链”、原作者联系方式或原演示品牌；开源许可证与必须保留的归属声明仅保留在许可证/合规文件中。
13. 后端运行在 PHP 8.3 与仍受安全支持的 Laravel 13；管理端使用仍受支持的 Vue/Vite 工具链。Composer 与管理端生产依赖审计不得含未处置的 high/critical 公告，所有较低等级残余必须在发布证据中逐项记录。

## 3. 范围

### 3.1 纳入范围

- 公开配置、图片验证码、短信验证码、注册、登录、找回密码、修改密码和用户信息。
- 管理员、普通用户、代理邀请关系和租户数据隔离；支付佣金计算除外。
- 首页统计、公告、素材分类、素材上传、域名和小程序池管理。
- 体验套餐、后台人工开通套餐、会员生效/到期和权益限制；公开价格和在线购买除外。
- 链接类型：微信小程序、金山文档、草料二维码、企业微信、个人微信二维码、腾讯优码。
- 链接列表、详情、分享地址、访问记录、UV 统计和二维码轮换。
- 链接记录永久保留，只有人工删除才移除；会员到期时暂停访问，重新开通会员后恢复，无单独链接续期概念。
- uni-app 二维码落地页的整理、可重复构建和接口对接。
- 安装、升级、备份、回滚、日志和运行任务。

### 3.2 明确排除

- 套餐公开价格、月付/年付购买页面。
- 微信支付、支付宝、支付回调、退款、自动续费、发票和财务对账。
- 由支付触发的一级/二级佣金结算。
- 企业团队、子账号、席位权限和多工作区。
- 与二维码落地无关的 uni-app 模板工具页面扩展。

支付排除范围按以下矩阵落实，不能暴露已知不可用的支付链路：

- 公开首页、套餐说明和会员中心不展示价格、购买按钮或优惠文案。
- `BuyVip`、支付配置、支付记录、佣金记录和支付相关菜单从普通用户及管理员导航中隐藏；历史支付数据仅保留在数据库，不提供变更入口。
- `/buy-vip`、微信支付回调和退款入口不注册为可变更业务状态的路由；若为兼容旧客户端保留，则统一返回 `PAYMENTS_DISABLED`，且不得创建或更新任何支付记录。
- `/config` 不向公开客户端返回套餐价格或支付凭据。
- `link-renewal`、代理套餐、代理等级和支付佣金等支付相邻能力从第一阶段 UI 移除，不留下可点击但返回 404 的入口。

## 4. 架构设计

### 4.1 业务边界

第一阶段继续采用“一名用户即一个租户”。所有链接、素材和自建小程序必须按 `user_id` 隔离；管理员跨租户操作必须显式经过管理员中间件，不能依赖前端菜单隐藏。

`serve/` 是业务事实来源，`admin/` 只消费稳定 API；`jump/` 只负责承载外部落地页；`mini_programs/` 只负责微信内的二维码展示。外部平台返回值必须先由后端验证，再转换成统一跳转结果。

唯一 SaaS 实例使用一个 `PUBLIC_ORIGIN` 作为 canonical origin，由部署环境注入，不写入构建产物源码。路由关系固定为：管理端 `${PUBLIC_ORIGIN}/web`、API `${PUBLIC_ORIGIN}/api`、分享页 `${PUBLIC_ORIGIN}/?code={code}`、内部跳转页 `${PUBLIC_ORIGIN}/j/{code}`。管理端和分享页都使用相对 `/api` 请求，因此浏览器主链路不需要跨域。

管理员添加的其他分享域名必须解析到同一 SaaS 实例、配置有效 HTTPS 证书并进入 `ALLOWED_SHARE_HOSTS`；Nginx 为每个域名提供相同的分享页、`/j` 和 `/api` 反向代理。Cookie 仅在各自分享域名生效。uni-app 使用 canonical `${PUBLIC_ORIGIN}/api`，该域名必须加入微信小程序 request 合法域名。DNS 由运营方在云平台配置，本项目只读验证解析结果；数据库迁移、密钥和服务器运维均为运营方动作，不属于普通用户安装流程。生产运行不允许继续依赖直接编辑 `admin/dist/config.js` 或 `jump/a_dev.html`。

统一托管版本不提供公网 Web 安装器；`/install` 路由、写 `.env` 和导入 SQL dump 的页面流程移除。安装、迁移、Seeder 和首次管理员创建只允许通过受控 CLI 完成，数据库不可用时公开页面返回无内部细节的 503。

### 4.2 会员与权益

新增 `EntitlementService` 作为唯一权益入口，集中完成：

- 判断用户是否为管理员、体验中、会员生效中或已到期。
- 计算以 `start_at` 为锚点的当前滚动月周期。
- 获取链接数、小程序池数、允许链接类型、自定义落地页和 UV 上限。
- 返回稳定的业务错误码，供管理端和公开跳转页展示。

现有 `users.vip_id/start_at/end_at` 在支付阶段前继续作为会员状态来源，但所有控制器不再各自复制时间与额度判断。`VipExpired` 定时任务修正后每小时处理到期状态，且必须幂等。

后台人工开通、续期、换套餐和撤销统一由 `MembershipService` 在数据库事务内执行，并始终创建 `vip_logs` 审计流水，记录操作者、来源、原因、旧状态和新状态：

- 无有效会员时的首次开通或过期后重新开通从当前时间开始，并建立新锚点。
- 有效期内同套餐重复开通属于续期，从当前 `end_at` 顺延，锚点不变。
- 有效期内升级立即生效并保留原剩余时长；新套餐的链接数、小程序池数和 UV 上限立即生效，滚动周期锚点和当前已用 UV 不重置。
- 降级记录为待生效，在当前周期结束时切换；切换后沿用原锚点并开始新的额度周期。
- 人工撤销立即失效并保留审计流水。

所有请求实时按当前时间判断权益，不能依赖每小时任务决定是否允许访问；定时任务只负责状态投影、待生效切换和告警。失败任务可安全重试，不得重复生成流水。

`vip_logs` 增加 `actor_user_id`、`action`、`reason`、`before_snapshot`、`after_snapshot`、`effective_at` 和唯一 `idempotency_key`；待生效降级保存在明确的会员变更记录中，不能依赖修改历史流水推断。

### 4.3 跳转解析

将当前 `JumpController` 中的类型分支拆成一个协调器和六个处理器：

- `MiniProgramTargetResolver`
- `KingDocTargetResolver`
- `CliQrTargetResolver`
- `WorkWechatTargetResolver`
- `LandingMiniTargetResolver`
- `QqQrTargetResolver`

处理器输入为已验证的链接配置与设备标识，输出统一的 `TargetResult`，包含标题、描述、图标、目标地址和可选二维码信息。协调器负责会员、过期、额度、缓存和访问日志，处理器只负责类型特有的目标生成。

外部 HTTP 调用统一使用 Laravel HTTP Client，设置连接/响应超时、有限重试和结构校验，禁止继续使用无超时的 `file_get_contents()`。测试中注入伪造客户端；测试环境真实验收时再使用对应外部服务。

`link-target` 与 `link-show-qr` 共用同一个 `LinkAccessPolicy`。访问前依次校验链接启用状态、所属用户启用状态、实时会员状态和套餐额度。拒绝原因使用 `LINK_DISABLED`、`USER_DISABLED`、`MEMBERSHIP_EXPIRED`、`QUOTA_EXCEEDED` 等稳定错误码；被拒绝的请求不得写访问日志。

链接状态拆分为人工状态和健康状态：`manual_status` 只能由有权限的用户或管理员修改，`health_status` 只能由外部健康检查任务修改；实际可用状态由两者和会员状态共同计算。健康检查任务不得自动重新启用人工停用的链接。现有 `status` 数据迁移到 `manual_status`，所有链接的 `expired_at` 迁移为空并停止用于访问判断，链接到期/续期任务与 UI 被删除。API 同时返回人工状态、健康状态和最终状态。

链接创建、编辑和跳转时都校验 `config.min_id`：只能引用当前用户自己的小程序，或管理员标记为官方池且当前套餐允许使用的小程序。跨租户 ID 返回权限错误；管理员跨租户操作写入审计日志。

分享地址由服务端统一生成：优先使用链接已选择、启用且位于 `ALLOWED_SHARE_HOSTS` 的分享域名，否则使用 `PUBLIC_ORIGIN`，格式固定为 `{origin}/?code={code}`。微信小程序和个人微信二维码即使不保存 `config.domain_id` 也必须得到 canonical 分享地址。六类类型分别建立 API 断言。

小程序凭据不得进入 `TargetResult`、响应缓存或 `link_visit_logs`。Secret 使用应用层加密字段保存，创建/更新接口只写入不回显，列表和详情只返回是否已配置及掩码。凭据轮换与失效均写管理员审计日志。

### 4.4 二维码轮换

新增独立 `QrRotationService`，负责：

- 过滤已过期或已达到单码额度的二维码。
- 按顺序或随机策略选择下一个二维码。
- 使用原子锁避免并发访问重复更新顺序索引。
- 按累计或自然日更新单码计数。
- 在无可用二维码时返回稳定业务错误，不产生空访问日志。

二维码过期时间必须读取每一项的 `expired_at`，不能使用未初始化变量。顺序模式跳过已过期/超限二维码后继续轮转；随机模式只在可用集合中选择。选择与额度占用通过 Redis Lua 脚本或等价原子操作一次完成，保证并发下不会超过单码上限。自然日计数使用 `Asia/Shanghai`，键在次日后保留 48 小时；累计计数保留到链接删除。

设备标识由服务端签发的随机 `visitor_id` Cookie 提供，客户端传入的 `device_uid` 不能直接作为可信额度凭据。Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`，作用域为当前分享域名，有效期一年。不同顶级分享域名无法共享 Cookie，同一物理访客跨域时可能被重复计数；这是偏保守的额度边界，不会少计用量。

账号 UV 在 `link-target` 成功解析前完成一次计量。只有个人微信二维码 `LANDING_MINI` 需要在小程序内再次读取已选择的二维码，因此后端仅为该类型用独立密钥把 `visitor_id`、链接代码和十分钟过期时间进行认证加密，生成不可解读且防篡改的 `visitor_token`；普通微信小程序 `MINI_PROGRAM` 不携带 visitor token，也不向客户小程序传递访客身份。

`news.vue` 接收 `code` 和 `visitor_token`，将 token 原样提交给 `link-show-qr`；后端完成认证解密并验证链接绑定和过期时间后读取首次解析时已选择的二维码，且该第二次请求不重复消耗账号 UV。原始 `visitor_id` 不暴露到 URL。IP 与 User-Agent 只保存使用独立环境密钥计算的不可逆哈希，用于滥用检测，保留 30 天后清理；原始 IP/User-Agent 不进入长期统计表。

### 4.5 UV 与滚动额度

套餐 UV 上限定义为“账号级、所有链接合计”的滚动月 UV，不是每条链接分别享有一份额度。每条链接仍保留独立访问统计，个人微信二维码另有单码额度。

- 额度窗口使用半开区间 `[period_start, period_end)`，时区固定为 `Asia/Shanghai`。
- `period_start` 以会员首次开通时间为锚点；目标月份没有锚点日时使用该月最后一天，但后续月份仍以原始锚点日计算。
- 账号级 UV 按周期内不同 `visitor_id` 去重，同一访客访问多个链接只计一个账号 UV；每条链接的统计则在该链接内去重。
- 体验、人工开通和过期后重新开通建立新锚点；同套餐续期不改变锚点；升级不改变锚点；降级在当前周期结束后沿用原锚点。
- 周期起点计入、终点不计入。必须覆盖 29/30/31 日、闰年、周期边界、多链接合计和重复访客测试。

账号级额度使用数据库原子计量，不以先查询后写入的非原子流程实现：`usage_periods` 对 `(user_id, period_start)` 唯一，保存 `used_uv`；`usage_visitors` 对 `(usage_period_id, visitor_hash)` 唯一。访问事务锁定 `usage_periods`：已存在访客始终允许继续访问；新访客在额度已满时返回 `QUOTA_EXCEEDED`，否则插入访客并原子增加 `used_uv`。`/home` 与套餐拦截都读取同一 `usage_periods.used_uv`，不得各算一套。

### 4.6 数据库与初始化

Laravel migrations 和 seeders 成为唯一的全新安装来源：

- 补齐 Sanctum `personal_access_tokens`、会员审计、额度周期、访客去重和其他范围内代码实际依赖的表；支付佣金相关缺失模型/表引用从非支付流程中移除，不为未实现业务虚构表结构。
- 将 `base.sql` 和 `packages.sql` 中必要的初始化数据转换为幂等 Seeder。
- 不在生产迁移中保留开发机地址、测试邮箱或固定密钥。
- 为短码、用户归属、访问统计、支付外的关键查询补充必要索引和唯一约束。
- 现有生产数据使用向前兼容迁移，迁移前备份，失败时回滚应用版本而不破坏已有数据。

发布阻断命令包括：空数据库执行 `php artisan migrate:fresh --seed` 成功；Seeder 连续执行两次无重复数据；旧数据执行升级迁移成功。运行时初始化不再读取 `base.sql` 或 `packages.sql`，六种 `allow_type` 键必须齐全。

## 5. 前端与小程序设计

### 5.1 管理端

- `/config` 请求失败时仍挂载应用，并显示可恢复的错误页，避免白屏。
- 登录状态以真实 token 字符串判断，退出只清理本应用使用的存储键。
- CRUD 请求统一展示验证错误、权限错误、外部服务错误和网络超时。
- 所有链接创建表单与后端枚举、校验规则保持一致。
- 不可用的支付与佣金入口在第一阶段隐藏，并标注为后续能力。
- 补充类型检查和最小 Playwright 端到端测试，不运行会自动改写源码的 lint 命令作为只读检查。
- 对前端全部 API 调用做清单核对：非支付能力必须存在后端路由和测试；支付相邻能力必须删除入口。`material-base64` 若仍被上传流程使用则实现并验证，不能保留隐含 404。
- 链接启停、删除、详情和分享地址必须有可操作入口，并在操作后重新读取 API 状态确认；不能仅依赖成功提示。

第一阶段最终 API 清单如下，代码和 UI 必须逐项对齐：

- 保留并验证：`config`、图片/短信验证码、注册/登录/找回密码/改密/用户信息、素材分类、素材上传/删除、`material-base64`、首页、公告、域名、小程序池、六类链接、链接下拉、邀请记录、管理员公告/域名/套餐权益/用户/代理树。
- 邀请功能仅包含不可变的 `parent_id` 推荐关系、唯一 `referral_code` 和直属邀请记录，不包含代理套餐、代理等级或佣金。有效推荐码可注册；无效码返回 422；手机号重复、自推荐和注册后换推荐人均被拒绝；并发注册不能重复绑定。
- 移除或隐藏：`link-renewal`、`agent-packages`、`agent-level`、`commission-logs`、`payments`、`buy-vip`、支付配置和支付回调。
- 前端构建前生成 API 使用清单，并与 `route:list` 自动比对；任何未列入明确排除项的前端请求出现 404 都是发布阻断。

链接管理使用以下明确契约：

| 操作 | API | 成功回读 | 失败要求 |
| --- | --- | --- | --- |
| 创建 | `POST /links` | `GET /links/{id}` 返回相同类型、归属和 canonical 分享地址 | 422 返回字段错误；越权引用返回权限错误 |
| 编辑 | `PUT /links/{id}` | 详情返回更新后的配置且 Secret 不回显 | 非本人资源返回 403 |
| 启停 | `PATCH /links/{id}/status` | 列表和详情同时返回新的 `manual_status/effective_status` | 非法状态返回 422 |
| 删除 | `DELETE /links/{id}` | 列表不再包含该链接，公开访问返回不存在 | 重复删除不得产生额外副作用 |
| 分享 | `GET /links/{id}` | 六类链接均返回非空 `share_link` | 未配置可用 origin 时返回配置错误而非空字符串 |

### 5.2 落地页与 postMessage

canonical 分享地址保持 `{PUBLIC_ORIGIN}/?code={code}`。Laravel 根路由在存在合法 `code` 时渲染 `serve/resources/views/jump/shell.blade.php`，无 `code` 时才渲染白标营销首页；分享壳 iframe 指向同源 `/j/{code}`。现有 `jump/a_dev.html` 的功能迁入该 Blade 后删除，避免独立静态文件与 Nginx/域名配置漂移。分享壳必须校验 `event.origin` 和 `event.source`，只接受预期 iframe 的消息；目标 URL 必须经过协议和域名策略验证。

### 5.3 uni-app

保留并打磨二维码展示页 `pages/views/tools/news` 及其必要依赖，并在 `pages.json` 中固定注册该路径；无关模板页面不进入首发导航。官方落地小程序池的 `url` 固定为 `pages/views/tools/news`。普通小程序链接的页面路径必须匹配 `^pages/[A-Za-z0-9_/-]+$`，不允许协议、域名或查询串。

`news.vue` 只接受 `code` 和 `visitor_token`，调用 `${PUBLIC_ORIGIN}/api/link-show-qr/{code}`，成功时展示标题、头像和二维码，token 无效/过期或无可用二维码时显示明确失败页。请求基础地址通过环境配置注入，微信 AppID 和 Secret 不提交到公开仓库。

真实发布使用微信开发者工具导入 `mp-weixin` 构建产物，在本地私有配置中绑定 AppID，上传测试版本并生成体验二维码。验收必须记录：编译成功、页面路径正确、体验版可打开、Scheme 进入该页面、两台手机展示预期二维码。仅存在源码页不算发布通过。

### 5.4 白标与品牌配置

产品品牌不得继续硬编码在 Vue、Blade、HTML、小程序页面或构建产物中。新增统一 `BrandConfig`，至少包含产品正式名称、简称、Logo、favicon、页面标题、客服入口、版权主体、备案信息和帮助中心地址；管理端、公开分享页、登录注册页与小程序从同一配置源读取。

正式品牌名称未确定时使用非公开的开发占位值，不以“火星快链”作为默认值。上线前对源码和构建产物执行旧品牌残留扫描，禁止出现“火星快链”、`mayilink`、原作者微信、演示账号密码和原演示域名。根 `LICENSE`、第三方许可证及依法/依许可证必须保留的 NOTICE 不属于营销品牌，不得为白标目的删除。

## 6. 错误处理与安全

- 公共 API 使用稳定的业务错误码与用户可理解的信息，日志记录内部异常但不向客户端返回堆栈或密钥。
- 登录、验证码、找回密码和公开跳转接口设置分层限流。
- 短码、链接配置、外部 URL、上传文件类型和大小进行服务端验证。
- 小程序 Secret、短信密钥和第三方凭据不写入 Git；生产配置从环境变量或受控配置存储读取，必要字段加密保存。
- 停止跟踪真实 `.env`，提供无密钥的 `.env.example`，上线前轮换已进入历史的应用密钥和外部凭据。
- 公开演示账号不得复用生产管理员密码。
- CORS、可信代理、Cookie/Token、Nginx 上传大小和静态文件目录按测试域名明确配置。

外部目标采用按类型的 allowlist：小程序路径只能是相对页面路径；金山文档仅接受 `https://kdocs.cn/l/{id}`；草料仅接受 `https://qr61.cn/`；企业微信仅接受经管理员配置的 `work.weixin.qq.com` 路径；腾讯优码仅接受 `https://ym.link/`。外部客户端禁止访问私网、环回、链路本地和保留地址，最多跟随 3 次且每次重新校验的 HTTPS 重定向。最终目标只允许 `https://` 或经处理器明确产生的 `weixin://` Scheme。HTML/JSON 结构不符合预期时返回类型专属外部服务错误码。

安全发布阻断门包括：从 Git 索引移除 `serve/.env`、`admin/.env` 和 `admin/.env.development`，补齐忽略规则与无密钥示例；轮换曾进入仓库历史的 `APP_KEY` 和第三方凭据；删除 README 和初始化数据中的默认管理员密码；首次管理员必须通过受控命令创建并强制首次改密。共享历史不重写，但必须完成密钥轮换、工作树扫描和提交内容扫描，并保留结果。

## 7. 测试设计

### 7.1 自动化测试

后端测试使用独立测试数据库与数组/测试缓存，禁止连接开发或生产数据库、发送真实邮件或输出 token。

`phpunit.xml` 必须显式指定测试数据库和测试邮件/队列驱动；现有发送邮件、`dd()` token 和修改固定用户/VIP 的测试必须删除或改写为隔离测试。测试启动时若检测到数据库名、主机或环境不符合测试白名单，立即失败。

- 单元测试：滚动月周期边界、29–31 日锚点、会员首次开通/续期/升级/降级/撤销、二维码过滤/顺序/随机、权益判断、认证加密 visitor token 和各处理器响应解析。
- 功能测试：注册登录、有效/无效推荐码、自推荐/重复注册、邀请记录、权限隔离、素材/域名/小程序/链接 CRUD、链接数与小程序数限制、会员到期，以及跨租户小程序引用。
- 集成测试：六类跳转的成功、超时、外部错误、无效配置、账号 UV 上限、已计访客在满额后的重复访问、并发新访客不超额和多链接合计。
- 安全测试：API、缓存、访问日志和数据库无明文 Secret；SSRF 私网目标和非法重定向被拒绝；链接停用、用户禁用、会员过期和越权请求不写访问日志。
- 回归测试：修复每个已确认缺陷前先增加失败用例，修复后保持通过。

管理端执行类型检查与生产构建，并使用 Playwright 覆盖登录、人工开通会员、创建六类链接、查看分享地址和错误提示。

### 7.2 运行与设备验收

测试环境按证据通道分别验收：

1. 代码/构建：静态检查、自动化测试和构建通过。
2. 服务运行：Nginx、PHP-FPM、MySQL、Redis、队列、Scheduler 均为健康状态。
3. API/管理端：验证路由特有响应体，不能只看 HTTP 200。
4. 浏览器：管理员和会员的完整操作流程通过。
5. 手机：至少两台设备验证六类链接、二维码轮换和 UV 去重。
6. 外部平台：使用真实测试凭据验证微信、小程序、金山文档、草料和腾讯优码；凭据缺失时明确列为未完成的外部门槛。

六类真实验收分别记录：输入配置、预期目标类型、API 响应字段、适用环境、Android 结果、iOS 结果和证据文件。微信小程序/个人微信二维码预期得到微信 Scheme 并在微信中打开指定页面；企业微信预期打开已配置的官方链接；金山文档、草料和腾讯优码分别验证其官方外部响应和最终 Scheme。任何一类没有真实凭据或有效测试链接时，该类状态为“外部阻塞”，不能归入通过。

## 8. 部署与回滚

- 使用独立测试子域名，不覆盖现有站点和 DNS 记录。
- 服务器部署前记录现有 Nginx 站点、端口、PHP 版本、数据库和磁盘状态，并建立配置与数据库备份。
- 管理端在受控构建环境生成静态产物；服务器仅运行 Nginx、PHP-FPM、MySQL、Redis、队列和 Scheduler，避免 2 GB 内存服务器同时承担前端依赖安装。
- 使用独立应用目录、数据库、系统用户和日志目录，避免与同机服务共享可写目录。
- Nginx 配置测试通过后再 reload；HTTPS 证书签发后验证自动续期。
- 部署失败时恢复旧 Nginx 配置、旧应用软链接和数据库备份，DNS 无需回退即可返回维护页。

生产进程由 systemd 或 Supervisor 管理 PHP-FPM/队列 Worker，Scheduler 使用系统 cron 每分钟执行 `php artisan schedule:run`。部署验收必须提供进程存活、失败自动重启、队列消费、定时任务执行记录和日志轮转证据；`.env` 不得继续使用 `QUEUE_CONNECTION=sync` 作为生产配置。

## 9. 实施顺序

虽然最终一次性交付全功能版本，内部实施仍按依赖顺序推进：

1. 建立隔离测试环境，补全 migrations/seeders 和安全配置。
2. 修复认证、权限、会员有效期和权益服务。
3. 修复素材、域名、小程序池和链接 CRUD。
4. 重构并验证六类跳转处理器与二维码轮换。
5. 修复管理端、落地页和 uni-app 构建链。
6. 完成自动化、浏览器、部署和手机验收。
7. 所有非支付门槛通过后，另行设计并实现付费订阅。

以下信息由用户在受控环境配置，不通过聊天或公开仓库传递：

- 微信小程序 AppID、Secret 与可测试的已发布小程序。
- 阿里短信账号、签名和模板，以及邮箱验证码模式所需的 SMTP 账号。
